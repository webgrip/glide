# Implementation coordination contract

This file records the initial API agreed by the implementation team. The public API guide will describe validated behavior.

Runtime and domain types live in `src/types.ts`. Node 24 executes TypeScript with native type stripping; keep TypeScript erasable. Production runtime has no third-party npm dependencies. Browser uses native ES modules.

Root owns `src/main.ts`, `src/http.ts`, `src/auth.ts`, `src/config.ts`, public UI, root package and integration. Core agent owns `src/store.ts`, `src/engine.ts`, `src/runtime/demo.ts`, core tests and the order-service demo fixture. Runtime agent owns `src/runtime/opencode.ts`, `src/runtime/command.ts`, runner examples, adapter tests. Infrastructure agent owns `src/runtime/workspace.ts`, `src/runtime/kubernetes.ts`, `src/broker.ts`, deployment and their tests. Docs agent owns docs excluding this file, skills, README and CI/check scripts. Review agent owns independent API/security tests after APIs exist. Changes to shared types require coordinating with root.

HTTP JSON shape: errors `{error:{code,message}}`; successful responses are direct objects/arrays. `GET /api/bootstrap` yields `{user,mode,repositories,crews,models,runtimes,maxBudgetUsd}`; unauthenticated bootstrap yields 401 in live mode. Demo auto-user only in explicitly enabled demo mode. `POST /api/login {name,password}`, `POST /api/logout`. `GET /api/sessions` array; `POST /api/sessions {title,objective,repositoryId,crewId,runtime,budgetUsd,trackerUrl?}` yields Session. `GET /api/sessions/:id` yields Session. `POST /api/sessions/:id/start`, `/pause`, `/resume`, `/cancel` yield Session. `POST /api/sessions/:id/messages {text}` yields Session (persisted instructions, live interrupt/restart only through explicit pause/resume). `POST /api/sessions/:id/budget {amountUsd}` adds explicit authorization up to max total (admin only). `GET /api/sessions/:id/events?after=N` SSE durable replay with numeric SSE id and data = Event. `GET /api/sessions/:id/history?after=N` JSON Event[]. `GET /api/sessions/:id/permissions` PermissionRequest[]. `POST /api/sessions/:id/permissions/:requestId {decision?,answers?}`. `GET /api/health` readiness; `/healthz` liveness. `GET /api/ploeg` is a read-only configured queue/health connector; no fabricated tracker writes.

Store proposed API: constructor(path), close(), saveSession(Session), getSession(id):Session|undefined, listSessions():Session[], appendEvent(sessionId,type,actor,data,runId?):Event, events(sessionId,after?):Event[], savePermission(PermissionRequest), permissions(sessionId):PermissionRequest[], getPermission(id), getUserByName(name), getUser(id), addUser({id,name,role,passwordHash}), createLogin(tokenHash,userId,expiresAt), getLogin(tokenHash), deleteLogin(tokenHash). Store schema may add encrypted/internal credential state with no API exposure. Session writes + event can expose transaction helper. Core agent must confirm signatures early.

Engine proposed API constructor(store,config,runtimes,broker?), create(input,user):Session, start(id,user):Promise<Session>, pause(id,user):Promise<Session>, resume(id,user):Promise<Session>, cancel(id,user):Promise<Session>, message(id,text,user):Session, addBudget(id,amount,user):Promise<Session>, respond(id,requestId,answer,user):Promise<Session>, recover():void, shutdown():Promise<void>. Start returns promptly while background work runs. Errors carry status/code. HTTP enforces object ownership; engine also validates lifecycle. Broker proposed API mint(session):Promise<Credential>, spend(reference):Promise<number|undefined>, revoke(reference):Promise<void>, extend(reference,totalBudget):Promise<void>. Unknown spend stays unknown and cannot silently become zero. Demo uses no broker or paid model.

All user-controlled rendered text must be escaped. Restrict repository/crew/runtime/model to configuration IDs. No arbitrary URLs or commands in user payloads. Spawn argv arrays without shell. No credentials in events, API responses or artifacts. Remote calls use bounded timeouts and preserve errors without returning credential-bearing bodies. Persistent SQLite is single-server/single-replica PoC storage, not distributed coordination. Kubernetes provisioning is genuine source integration but requires a configured cluster for a live deployment test.
